# Plan: Narrate Tool Calls via TTS

## High-Level Goal

When the voice agent executes a tool call (e.g. checking inbox, reading an email), the user currently hears silence until the result comes back. We want to speak a short phrase like "Checking your inbox." before the tool executes, so the user knows something is happening.

Each tool can optionally have a narration phrase. If no phrase is configured, the tool executes silently (no change in behavior).

## Important Technical Notes

### TTSSpeakFrame with append_to_context=False

The narration must use `TTSSpeakFrame(text, append_to_context=False)` so the short phrase is spoken but **not** added to the LLM conversation context. Otherwise the LLM would see its own narration as part of the conversation history and might get confused.

### Narration runs before the IMAP lock

The `await tts.queue_frame(...)` call happens **before** `async with imap_lock:`, so the narration is queued immediately and the TTS can start speaking while the tool waits for the lock. This is intentional -- the whole point is to fill the silence during the wait.

### queue_frame is non-blocking

`tts.queue_frame()` enqueues a frame into the pipeline. It does not wait for the audio to finish playing. The tool execution proceeds in parallel with the speech, which is the desired behavior.

### TTS cost impact

Each narration phrase adds ~20 characters to the Deepgram TTS bill per tool call. This is negligible but tracked automatically by `TrackedDeepgramTTSService`.

### Approval-gated tools get neutral phrasing

Tools like `send_email`, `archive_email`, and `delete_email` may be classified as needing user approval (via `classify_action`). If the narration says "Sending that email." but the tool returns "pending approval", it is misleading. Use neutral phrases like "On it." for these tools.

## Phases

### Phase 1: Add TOOL_NARRATIONS constant
- [ ] Add `TOOL_NARRATIONS: dict[str, str]` to the CONSTANTS section
- [ ] Include entries for 8 user-facing email tools
- [ ] Omit instant/silent tools (mark_as_read, save_memory, submit_feature_request)

### Phase 2: Wire up TTS to the handler
- [ ] Add `TTSSpeakFrame` to the import from `pipecat.frames.frames`
- [ ] Add `tts: TrackedDeepgramTTSService` parameter to `_register_tool_handler`
- [ ] Pass `tts=tts` in the `create_pipeline` loop that calls `_register_tool_handler`

### Phase 3: Speak narration in the handler
- [ ] At the top of the inner `handler` function, look up `TOOL_NARRATIONS.get(function_name)`
- [ ] If a phrase is found, `await tts.queue_frame(TTSSpeakFrame(narration, append_to_context=False))`
- [ ] If not found, do nothing (silent execution, same as before)

---

## Success Criteria

- [ ] Tools with a narration entry speak a short phrase before executing
- [ ] Tools without a narration entry execute silently (no regression)
- [ ] Narration does NOT appear in the LLM conversation context
- [ ] Narration is queued before the IMAP lock so speech starts during any wait
- [ ] Adding/removing narrations for future tools only requires editing the `TOOL_NARRATIONS` dict
