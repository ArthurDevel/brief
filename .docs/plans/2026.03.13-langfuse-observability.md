# Langfuse Observability for Voice Sessions

## Status

Future work -- not part of MVP. To be detailed later.

## Context

Langfuse has no native OpenAI Realtime API integration (open feature requests: #3765, #4757, #9314). We can use the low-level Langfuse JS SDK to manually trace voice sessions since all relevant data already flows through our voice gateway.

## What to Trace

### Per session (1 Langfuse trace per phone call)

- **Trace metadata**: userId, sessionId, duration, phone number
- **User transcript turns**: from `conversation.item.input_audio_transcription.completed` events
- **Assistant transcript turns**: from `response.audio_transcript.done` events
- **Tool calls**: name, arguments, result, latency -- from our `handleToolCall` interception
- **Token usage**: input_tokens + output_tokens from `response.done` events
- **Cost**: calculated from token counts + audio duration (OpenAI bills audio separately)
- **Errors**: IMAP failures, OpenAI errors, timeouts

### Trace structure

```
Trace (1 per call session)
  ├── Generation (1 per model turn -- assistant response)
  │     input: user transcript text
  │     output: assistant transcript text
  │     usage: { input_tokens, output_tokens }
  │     metadata: { voice, model }
  ├── Span (1 per tool call)
  │     name: tool name
  │     input: tool arguments
  │     output: tool result
  │     metadata: { classification, action_id, status }
  └── Span (session-level)
        metadata: { total_duration, total_tokens, action_count }
```

## Integration Point

All tracing hooks go in `openai-relay.ts` -- it already intercepts every event type we need. Create a `langfuse-tracer.ts` in the voice gateway that wraps the Langfuse SDK and exposes simple methods:

- `startTrace(userId, sessionId)` -- creates trace
- `logGeneration(userText, assistantText, usage)` -- adds generation
- `logToolCall(name, args, result, durationMs)` -- adds span
- `endTrace()` -- finalizes and flushes

## Dependencies

- `langfuse` npm package (JS SDK)
- Langfuse cloud account or self-hosted instance
- Env vars: `LANGFUSE_PUBLIC_KEY`, `LANGFUSE_SECRET_KEY`, `LANGFUSE_BASE_URL`

## Open Questions

- Should we store audio files (S3) and link them in Langfuse metadata?
- How to attribute cost accurately (audio tokens vs text tokens have different rates)?
- Do we trace dashboard-triggered actions (approve/undo) as separate traces or link to the original session trace?
- When Langfuse ships native Realtime API support, how much of this can we drop?
