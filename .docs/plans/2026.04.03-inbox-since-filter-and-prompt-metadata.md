# Inbox "since" filter and prompt metadata enrichment

## High-level goal

When the AI greets the user with "You have 63 new emails since your last call," and the user asks to check their inbox, the AI should show those 63 emails -- not just the latest 20. This requires:

1. Adding a `since` parameter to the `list_inbox` tool so the LLM can filter by datetime
2. Fixing the email count to be time-accurate (not just date-accurate) so users who call multiple times per day get the right count
3. Enriching the system prompt with metadata (current date/time, user email address, last call datetime) so the LLM has the context to use the `since` parameter correctly

## Important technical notes

### IMAP SINCE is date-only, but we need time-granularity

IMAP's `SINCE` criterion operates at date granularity only. A user who calls multiple times per day would get an inflated count. The fix: use IMAP `SINCE` as a coarse filter (to avoid fetching the entire inbox), then filter in Python by comparing each email's `envelope.date` against the full datetime. This applies to both `count_emails_since` and `list_inbox`.

### `since` and `limit` are mutually exclusive for the LLM

When the LLM passes `since`, the `limit` parameter is ignored. The tool description should make this clear. Internally, `list_inbox` with `since` has a hardcoded cap of 100 emails to prevent unbounded fetches. This cap is an internal safety bound, not exposed to the LLM.

### Tool description as the LLM instruction point

The instruction to use `since` when listing new emails goes in the `list_inbox` tool description in `definitions.py`, not in `email_context`. This is because `email_context` can be `None` (first call or fetch failure), and the instruction should always be present and co-located with the tool schema.

### session.py (MODIFIED)

#### Types

```
SessionMetadata {
  current_datetime: str      # ISO 8601 formatted current date/time (with timezone)
  user_email: str            # The user's email address
  last_call_datetime: str | None  # ISO 8601 datetime of last call end, or None for first call
}
```

### prompt.py (MODIFIED)

#### Methods

| Method | Arguments | Returns | Description |
|--------|-----------|---------|-------------|
| `build_system_prompt` | `memory_entries: list[MemoryEntry], tool_approval_config: dict[str, str], email_context: str \| None, email_provider: str \| None, session_metadata: SessionMetadata \| None` | `str` | Extended with optional `session_metadata`. When provided, adds a "Session context" section. |

### definitions.py (MODIFIED)

No new types. The `list_inbox` tool schema gains an optional `since` property:

```json
"since": {
  "type": "string",
  "description": "ISO 8601 datetime. Only return emails received after this time. When used, the limit parameter is ignored."
}
```

Updated tool description:
```
"List recent emails in the user's inbox. When session context provides a last_call_datetime, use the since parameter to show only emails received since then."
```

### email_client.py (MODIFIED)

#### Methods

| Method | Arguments | Returns | Description |
|--------|-----------|---------|-------------|
| `list_inbox` | `client: IMAPClient, limit: int, since: datetime \| None = None` | `list[EmailSummary]` | When `since` is provided: uses IMAP SINCE (date) as coarse filter, then filters by envelope datetime in Python. Ignores `limit`, hardcoded cap of 100. When `since` is None: existing behavior unchanged. |
| `count_emails_since` | `client: IMAPClient, since: datetime` | `int` | Changed from `date` to `datetime`. Uses IMAP SINCE (date) as coarse filter, then counts only emails with envelope.date after the given datetime. |

### handlers.py (MODIFIED)

No new methods or types. The `list_inbox` branch:
- Extracts optional `since` ISO 8601 string from args
- Parses to `datetime` via `datetime.fromisoformat()` (returns error dict on invalid format)
- When `since` is present, passes it to `email_client.list_inbox` and ignores the `limit` arg
- Both `session_id` and non-`session_id` code paths handle `since`

### pipeline.py (MODIFIED)

No new methods or types. The `create_pipeline` function:
- Constructs `SessionMetadata` from `datetime.now(timezone.utc).isoformat()`, `imap_config.user`, and `last_ended_at.isoformat()` (or None)
- Passes full `last_ended_at` datetime (not just date) to `count_emails_since`
- Passes `SessionMetadata` to `build_system_prompt`

## Success criteria

- When the AI says "You have 63 new emails since your last call" and the user says "check my inbox," the LLM calls `list_inbox` with `since`, returning those emails (up to 100)
- `count_emails_since` is time-accurate: a user calling twice on the same day gets the correct count for the interval since their last call
- The system prompt contains the current datetime, user email address, and last call datetime
- The `list_inbox` tool description tells the LLM to use `since` when session context provides `last_call_datetime`
- When `since` is used, `limit` is ignored (clear to the LLM via the tool description)
- Invalid `since` values produce a user-friendly error, not a crash
- Existing `list_inbox` behavior (no `since` param) is unchanged
- All new and existing tests pass
