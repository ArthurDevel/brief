# Send Email Detail Modal + Convert to Draft

## High-Level Goal

Three changes:

1. **View email details**: Click any `send_email` action row to open a modal showing to, subject, and body. Only `send_email` rows are clickable.
2. **Convert to Draft**: Inside the modal, pending `send_email` actions show a "Convert to Draft" button. This creates a draft in the user's mailbox (via IMAP APPEND to the Drafts folder) from the action's arguments and marks the action as `"converted"`.
3. **Clean up send_email tool**: Remove `draft_id` from the `send_email` tool definition -- it should only accept `to`, `subject`, `body`.

## Important Technical Notes

### Button clicks must not trigger modal open

Action rows contain approve/reject buttons. The row `onClick` handler should check `(e.target as HTMLElement).closest("button")` -- if the click originated from a button, bail out. This prevents button clicks from also opening the modal.

### Convert-to-draft only needs IMAP, not SMTP

The `convert-to-draft` API route should NOT load SMTP credentials. `saveDraft()` works entirely through IMAP APPEND. This differs from the `approve` route which needs both IMAP and SMTP.

### convertActionToDraft must validate toolName and status

`convertActionToDraft` must verify `toolName === "send_email"` and `status === "pending"` before proceeding. Throw an error otherwise. This prevents misuse (e.g. converting an archive action).

### saveDraft returns UndoRecipe, extract draftUid from it

`saveDraft()` returns `UndoRecipe` with structure `{ operation: "delete_draft", params: { draftUid } }`. The `convertActionToDraft` function should extract `draftUid` from `recipe.params.draftUid` when building the result object.

### Body is plain text with possible newlines

Render the email body with `whitespace-pre-wrap` so line breaks are preserved.

### Validate tool_name before opening IMAP connection

In the `convert-to-draft` API route, load the action row and check `tool_name === "send_email"` and `status === "pending"` BEFORE opening the IMAP connection. This avoids wasting an IMAP connection on invalid requests.

### Error handling: keep action pending on failure

If `saveDraft` throws (e.g. IMAP connection drops) during convert-to-draft, the action should remain `"pending"`. Do NOT mark it as `"failed"`. Let the error propagate to the API route which returns a 500, and the frontend shows an error. The user can retry.

### Migration file naming

The Supabase CLI generates timestamped filenames. Rename the generated file to `013_action_converted_status.sql` to match the existing numeric prefix convention (001, 002, ... 012).

### Supabase migration via CLI

Create the migration file using the Supabase CLI:
```bash
npx supabase migration new action_converted_status
```
Then write the SQL into the generated file. Apply locally with `npx supabase db push` or the appropriate command for the environment.
