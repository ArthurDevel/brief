# Voice Behavior Eval Cases Plan

## Maintenance Instructions

After each implementation phase, check off the completed steps in this document.

When new findings come up during implementation, add them to the "Findings" section before continuing. This plan is intended to be usable by a new agent without prior conversation context.

Do not assume a dataset case, judge change, or prompt change works because it looks correct in JSON. At each feedback point below, run the relevant evals, inspect pass/fail reasons, and update either the dataset, judge, or prompt before moving on.

## Goal

Add Langfuse `voice-behavior` prompt test cases based on production session `0f0d103d-b1ed-49f1-b395-0606c8caaf07`.

The cases should focus only on prompt behavior:

- Default one-by-one triage should present sender and subject, then ask a neutral question like "What would you like to do with it?"

## Dataset Structure Summary

Remote Langfuse dataset `voice-behavior` currently matches the local file with 24 items.

Each dataset item follows this shape:

- `id`
- `category`
- `goal`
- `tags`
- `input.session_context`
- `input.messages`
- `expected_output.required_tools`
- `expected_output.forbidden_tools`
- `expected_output.response_rules`
- `expected_output.style_tags`
- `expected_output.should_ask_follow_up`

Existing cases use realistic tool-call transcripts inside `input.messages`, including assistant tool calls and tool results as JSON strings.

## Proposed Test Cases

### 1. Neutral Triage Question

Suggested id: `triage_next_email_asks_neutral_what_to_do`

Goal: When going one by one and the next email is not a repeat of an action just taken, present exactly one email and ask neutrally what the user wants to do.

Use real data from session `0f0d103d-b1ed-49f1-b395-0606c8caaf07`:

- Include real `list_inbox` output from `2026-04-10T22:56:18.146Z`.
- Include the memory-triggered auto-actions that happened before the first assistant response:
  - `batch_delete_emails` for realtor.com IDs `19d7960ffd5163cd` and `19d78dcc19d0cb80`.
  - `move_to_folder` for Vercel IDs `19d7904e5778ce54` and `19d78ee887a93f1f` to `Dev/Github`.
  - `archive_email` for Google ID `19d7911d6749a7b3`.
- User says: `Hello. Yes, please.`
- The next remaining email is:
  - ID: `19d796d75829d243`
  - From: `HeyGen Notifications <no_reply@email.heygen.com>`
  - Subject: `Your Video is Ready!`

Expected behavior:

- No tool call.
- Present only the HeyGen sender and subject.
- Ask "What would you like to do with it?" or equivalent.
- Do not ask "Read it?", "Delete it?", "Skip?", "Archive it?", or offer multiple action suggestions.

### 2. Similar Email After Delete Can Suggest Delete Too

Suggested id: `triage_similar_email_after_delete_can_suggest_delete_too`

Goal: If the user just deleted one email and the next email is similar enough, the assistant may ask a focused "Delete this one too?"

Use real data from the same session:

- First shown email:
  - ID: `19d796d75829d243`
  - From: `HeyGen Notifications <no_reply@email.heygen.com>`
  - Subject: `Your Video is Ready!`
- User says: `Delete.`
- Assistant calls `delete_email` with `19d796d75829d243`.
- Tool returns queued/pending.
- Next email:
  - ID: `19d796260adb24b2`
  - From: `HeyGen Notifications <no_reply@email.heygen.com>`
  - Subject: `Your Video is Ready!`

Expected behavior:

- No immediate delete tool call for the second email.
- It is acceptable to say: `Queued. Next is also from HeyGen Notifications, subject Your Video is Ready. Delete this one too?`
- The test should explicitly allow this suggested action because the same sender and same or near-same subject immediately follow a delete action.

## Tradeoffs And Technical Implications

- The neutral-question case conflicts with the current judge's broad allowance for suggested follow-up actions. The judge should be updated so explicit dataset response rules take precedence over generic examples.
- The similar-email case prevents overcorrection. The assistant should avoid suggestions by default, but a repeated sender/subject immediately after a delete is useful enough to allow "Delete this one too?"
- Real session data should be preserved where it matters: email IDs, senders, subjects, key tool calls, and tool outputs. Irrelevant conversation should be trimmed to keep tests focused and cheaper to run.
- Do not add STT ambiguity cases. The user clarified the session had a bad microphone, and this work should focus on prompt behavior only.
- The search-result filtering concern is a product/backend issue. A GitHub issue exists for it, but do not add a prompt dataset case for it in this pass.
- Removed `triage_deepgram_inbox_no_category_guess` and `feature_request_filter_search_results_before_context` after user feedback that those tests were not correctly designed.

## Findings

- The local dataset and remote Langfuse `voice-behavior` dataset both had 22 items at review time.
- `langfuse/evals/upload_dataset.py` treats local JSON as source of truth and deletes remote stale items.
- `search_emails` results from the reviewed session can be noisy and large; GitHub issue 173 tracks adding a filtering step before LLM context injection.
- The voice assistant does not have a GitHub issue creation tool. It can only submit product feedback through `submit_feature_request`.
- The current judge prompt may need adjustment before adding the neutral-question case, because it currently treats many action-suggesting follow-ups as always acceptable.
- Baseline remote eval before changes: 16/22 passed, average score 0.727.
- Judge-check remote eval after judge edits: 14/22 passed, average score 0.636. Failures appeared to be existing prompt/model behavior or cheap-model nondeterminism rather than a blocker for the two focused cases.
- Added local dataset-file mode and `--item-id` filtering to `langfuse/evals/voice_behavior_eval.py` so new cases can be tested before upload.
- Initially added four cases, but removed `triage_deepgram_inbox_no_category_guess` and `feature_request_filter_search_results_before_context` after user feedback that those tests were wrong.
- Final accepted new cases: `triage_next_email_asks_neutral_what_to_do` and `triage_similar_email_after_delete_can_suggest_delete_too`.
- Local targeted eval for the final two cases: 2/2 passed.
- Final full local eval on the 24-item dataset: 14/24 passed. The two accepted new cases passed; remaining failures are broader existing eval/prompt issues such as greeting/listing behavior, redundant contact lookup, memory action batching, and search/no-results recovery.
- Remote Langfuse sync uploaded 24 items and deleted 2 stale removed cases.
- Remote targeted eval for the final two new cases: 2/2 passed, average score 1.000.
