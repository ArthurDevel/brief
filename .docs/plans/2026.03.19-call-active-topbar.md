# Call Active Top Bar

## High-Level Goal

When a web call is active, display a persistent bar at the top of the dashboard that:
- Indicates the call is in progress
- Allows the user to navigate back to the call page
- Remains visible on all dashboard pages while the call is alive

Currently, call state (`callActive`, `peerConnection`, `micStream`) lives locally in `CallPage`. Navigating away unmounts the component and kills the call. To keep the call alive across pages, we must lift the WebRTC session and call state into a shared React Context at the dashboard layout level.

## Per-File Methods and Types

### CallContext.tsx (NEW)

Context provider that manages WebRTC call state and exposes it to the entire dashboard.

#### Types

```
PipelineCallSession {
  peerConnection: RTCPeerConnection
  micStream: MediaStream
  remoteAudio: HTMLAudioElement
}

CallContextValue {
  callActive: boolean
  status: string
  error: string | null
  startCall: () => Promise<void>
  endCall: () => void
}
```

#### Methods

| Method | Arguments | Returns | Description |
|--------|-----------|---------|-------------|
| `CallProvider` | `{ children: React.ReactNode }` | `JSX.Element` | Context provider component. Holds `callActive`, `status`, `error` state and `pipelineSessionRef`. Exposes `startCall` and `endCall` via context value. |
| `useCall` | (none) | `CallContextValue` | Hook to consume the call context. Throws if used outside `CallProvider`. |
| `startCall` | (none) | `Promise<void>` | Authenticates with Supabase, requests mic, establishes WebRTC session via `startWebRTCSession`. Updates state throughout. |
| `endCall` | (none) | `void` | Closes peer connection, stops mic tracks, pauses and releases remoteAudio, resets state. |

Note: `startWebRTCSession` (the pure WebRTC setup function) moves from `call/page.tsx` into `CallContext.tsx` since the context now owns the session lifecycle. The types `PipelineCallSession`, `StartResponse`, and `OfferResponse` move with it.

## Important Technical Notes

### WebRTC session survives navigation

Because `CallProvider` wraps the dashboard layout, the provider never unmounts during dashboard navigation. The `peerConnection` and `micStream` refs persist in the provider. When the user navigates away from `/dashboard/call` and comes back, the call page re-reads state from context and shows the active call UI.

### Remote audio playback element

The `remoteAudio` element (created in `startWebRTCSession`) is not attached to the DOM -- it uses `new Audio()` with `autoplay = true`. This means audio playback continues regardless of which page the user is on, since the Audio object lives in memory (held by the context ref), not in the component tree.

### Stale closure risk in onconnectionstatechange

The `onconnectionstatechange` handler (set during `startCall`) references cleanup logic. In the current `call/page.tsx`, the handler calls `endCall()` directly -- this works by accident because `endCall` is a stable `useCallback` with empty deps. When moved into `CallProvider`, this becomes a stale closure risk. The handler must instead call a `cleanupSession` helper that only reads from `pipelineSessionRef.current` (a ref, not state) and then sets state. Do not call the context's `endCall` from inside the handler.

### Provider cleanup on unmount

Add a `useEffect` cleanup return in `CallProvider` that calls the cleanup logic when the provider unmounts (e.g., tab close, logout). This ensures the peer connection and mic stream are properly released.

## Success Criteria

- A call started on `/dashboard/call` remains active when navigating to other dashboard pages
- A top bar appears on all dashboard pages while a call is active, showing the call status
- Clicking the bar navigates back to `/dashboard/call`
- Ending the call (from the call page) removes the bar
- Audio playback continues uninterrupted during navigation
- No regression in existing call start/end behavior
