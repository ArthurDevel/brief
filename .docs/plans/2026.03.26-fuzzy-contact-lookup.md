# Fuzzy Contact Lookup

## High-Level Goal

Enable the voice agent to resolve spoken names (including mispronounced/non-English names) to email addresses. Build a per-user contacts index extracted from IMAP email headers, stored in Supabase with RLS, and expose a `find_contact` tool that does fuzzy + phonetic matching. Contacts are synced on inbox connect/change (full scan) and at end-of-session (incremental).

## Important Technical Notes

### Contact sync trigger from settings API (TypeScript -> Python)

When the user saves IMAP settings in the web app, the settings PUT route needs to trigger a full contact sync. Since the sync logic lives in the Python voice pipeline (which has IMAP access), the web app calls an internal API endpoint on the voice pipeline. The flow:

1. Settings PUT saves credentials to DB/Vault
2. If `imap_user` changed (or is new), POST to `{VOICE_PIPELINE_URL}/sync-contacts` with `user_id` and `Authorization: Bearer {INTERNAL_API_KEY}`
3. The voice pipeline endpoint loads the user's IMAP config from DB/Vault, runs the full scan, and upserts contacts

On inbox change (different `imap_user`), the settings route first deletes all existing contacts for the user, then triggers the sync. This avoids stale contacts from a previous inbox.

The settings route should `await` the POST to `/sync-contacts` (it returns quickly). The `/sync-contacts` endpoint accepts the request, queues the actual sync as a FastAPI `BackgroundTasks` job, and returns `{ status: "queued" }` immediately. This avoids the risk of the Next.js serverless function terminating before the request is sent.

If the user starts a voice call before the background sync completes, `find_contact` may return no results. This is expected -- contacts will populate in the background.

### find_contact does NOT use IMAP

The `find_contact` tool only queries Supabase for the user's contacts and runs the matching algorithm in-memory. It does not touch IMAP. Since `save_memory` and `submit_feature_request` already go through `imap_lock` in `pipeline.py` without issues (they only touch Supabase), `find_contact` follows the same pattern -- the lock overhead is negligible for a quick Supabase query.

### Incremental sync at session end

In `_cleanup_session` in `server.py`, after closing the IMAP connection and ending the session, trigger an incremental contact sync. This requires a fresh IMAP connection (the session one is already closed). Use `create_imap_connection(imap_holder["config"])` since the config is still available. The sync should be fire-and-forget -- wrapped in try/except so it never blocks session cleanup.

The incremental sync only fetches emails newer than the user's most recent `last_seen_at` in `user_contacts`. If no contacts exist yet (first-time user who hasn't connected via settings), skip the incremental sync.

### IMAP ENVELOPE parsing

Use IMAP ENVELOPE fetch (not BODY) -- ENVELOPE is pre-parsed by the server and fast. ENVELOPE returns structured address tuples `(name, route, mailbox, host)` per RFC 3501, NOT raw header strings. So instead of parsing `"Name" <email>` strings, use a `_parse_envelope_address` helper that extracts `display_name` from the name field and constructs `email` from `mailbox@host`.

### Concurrent sync prevention

Multiple sync triggers can overlap (e.g. settings save triggers a full sync, then a session ends and triggers incremental sync). To prevent concurrent scans for the same user, add a `contacts_synced_at` timestamp column to `user_settings`. Before starting any sync (full or incremental):

Use an atomic UPDATE with a WHERE clause to avoid a TOCTOU race (two processes reading the same stale timestamp and both proceeding):

```python
result = supabase.table("user_settings").update(
    {"contacts_synced_at": now_iso}
).eq("user_id", user_id).or_(
    f"contacts_synced_at.is.null,contacts_synced_at.lt.{threshold_iso}"
).execute()

if not result.data:
    return 0  # another process already claimed the sync
```

This turns the check + set into a single atomic operation. If `result.data` is empty, the row was not updated (meaning another sync is already running). No separate read needed.

This is safe against crashes: if a sync dies mid-way, the timestamp expires after 5 minutes and the next trigger retries. No stuck boolean flags.

The 5-minute cooldown is stored as a constant (`SYNC_COOLDOWN_SECONDS = 300`) in `contact_sync.py`.

### Sent folder discovery

The Sent folder name varies by provider (Gmail uses `[Gmail]/Sent Mail`, others use `Sent`, `INBOX.Sent`, etc.). Use the existing `resolve_special_use_folder(client, b'\\Sent')` function from `email_client.py` to discover the correct folder name at runtime.

### Matching algorithm

Two signals combined:
1. **Phonetic**: Metaphone encoding via `jellyfish.metaphone()`. Compare metaphone codes of each token in the query against each token in the contact name. Note: this is single Metaphone, not Double Metaphone (jellyfish does not provide Double Metaphone). Single Metaphone is sufficient for our use case since we combine it with string similarity.
2. **String similarity**: `rapidfuzz.fuzz.token_sort_ratio()` -- handles word reordering and partial matches.

Final score = `0.4 * phonetic_score + 0.4 * string_score + 0.2 * frequency_score`. Frequency is normalized (contact_freq / max_freq_in_list). Return contacts with score > 0.3, sorted descending, top 5.

For contacts with `display_name=None`, use the email local part (before `@`) as the name for matching purposes.

### contact_sync.py (NEW)

#### Types

```
ContactRecord {
  email: str
  display_name: str | None
  frequency: int
  last_seen_at: datetime
}
```

#### Methods

| Method | Arguments | Returns | Description |
|--------|-----------|---------|-------------|
| `full_sync` | `imap_config: ImapConfig, user_id: str, supabase: Client` | `int` | Checks `contacts_synced_at` -- if within `SYNC_COOLDOWN_SECONDS`, returns 0. Otherwise sets `contacts_synced_at = now()`, creates IMAP connection, scans last 500 sent + 500 inbox emails, extracts contacts, upserts to Supabase, closes connection. Returns number of contacts upserted. |
| `incremental_sync` | `imap_config: ImapConfig, user_id: str, supabase: Client` | `int` | Checks `contacts_synced_at` -- if within `SYNC_COOLDOWN_SECONDS`, returns 0. Fetches the most recent `last_seen_at` from user_contacts. If no contacts exist, skips (returns 0). Otherwise sets `contacts_synced_at = now()`, creates IMAP connection, scans emails newer than that date, upserts new/updated contacts, closes connection. Returns count. |
| `delete_user_contacts` | `user_id: str, supabase: Client` | `None` | Deletes all contacts for a user. Called when inbox is changed/removed. |
| `extract_contacts_from_imap` | `client: IMAPClient, folders: list[str], limit: int, since: date \| None` | `list[ContactRecord]` | Scans ENVELOPE data from specified folders. Uses `resolve_special_use_folder` for Sent folder discovery. Extracts From (inbox) and To/CC (sent) address tuples. Returns deduplicated contact records with frequency counts. |
| `_parse_envelope_address` | `addr: tuple` | `tuple[str \| None, str]` | Extracts `(display_name, email)` from IMAP ENVELOPE address tuple `(name, route, mailbox, host)`. Returns `(decoded_name, mailbox@host)`. |
| `_upsert_contacts` | `contacts: list[ContactRecord], user_id: str, supabase: Client` | `int` | Upserts contacts into user_contacts table. On conflict (user_id, email), updates display_name to the most recent, adds frequency, updates last_seen_at if newer. Returns count. |

#### Types

  display_name: str | None

#### Methods

| Method | Arguments | Returns | Description |
|--------|-----------|---------|-------------|

## Success Criteria

- `find_contact("john pierre dubwa")` returns "Jean-Pierre Dubois" as top match when that contact exists in the user's email history
- Contacts with no display name are handled gracefully (matched on email local part)
- Contacts are scoped per-user via RLS -- no cross-user leakage
- The voice pipeline always filters by `user_id` when querying contacts (service role bypasses RLS)
- Connecting a new inbox triggers a full scan of 500 sent + 500 inbox emails
- Changing inbox deletes old contacts and rescans
- End of session triggers incremental sync without blocking cleanup
- If no contacts exist yet, incremental sync is skipped
- The LLM uses `find_contact` before `draft_email`/`send_email` when the user provides a name
- Concurrent sync triggers for the same user are prevented by the `contacts_synced_at` cooldown (5 minutes)
- A crashed sync does not permanently block future syncs
- All tests pass
